## Основные понятия для чайников

**MTProto** — протокол, используемый Telegram для шифрованного обмена данными между клиентом и сервером.

**MTProto-прокси** — сервер-посредник, который принимает подключения от пользователей и перенаправляет их к серверам Telegram.

**Telemt, MTG, MTProto.zig и тд.** — разные реализации MTProto-прокси на разных языках (Rust, Go, Zig). Все выполняют одну задачу — поднимают прокси для Telegram.

**SYN** — первый пакет в TCP-рукопожатии (трёхэтапное установление соединения).

**MSS (Maximum Segment Size)** — максимальный размер сегмента данных в TCP-пакете. Урезание MSS может быть использовано для починки прокси, но замедляет загрузку медиа.

**Fake TLS** — маскировка прокси-трафика под обычный HTTPS (TLS).

**SelfSteal** — метод, при котором для Fake TLS используется SSL-сертификат реального сайта, подставленный на свой сервер.

**MiddleProxy** — режим работы прокси, при котором он не подключается напрямую к Telegram, а использует промежуточный прокси-сервер.

## Термины связанные с фиксом

**Фикс V1** — Разделение клиентов по портам: на один порт пускаются все устройства с SYN-лимитом 1 в сек. через DROP, на другой порт — iOS с урезанием MSS.

**Фикс V2** — один порт для всех устройств. iOS определяется по TTL+Length, применяется REJECT вместо DROP, SYN-лимит увеличен до 1 пакета в 1.1 сек, отключен MSS.

**Фикс V3** — как **V2**, но iOS определяется по полному отпечатку TCP-пакета (через u32/mangle) вместо TTL+Length. Более точное определение.

**SYN FIX / SYN Limit** — ограничение количества входящих SYN-пакетов с одного IP в секунду.

**REJECT vs DROP** — REJECT мгновенно сообщает клиенту об обрыве соединения (клиент сразу переподключается), DROP просто молча обрывает (клиент ждёт таймаут 3-5 секунд). REJECT быстрее.

**hashlimit** — модуль iptables для ограничения частоты пакетов

**TTL (Time To Live)** — поле в IP-пакете, указывающее, сколько узлов он может пройти. У iOS и Android/Desktop различается, используется для определения типа устройства.

**u32 (фильтр)** — модуль iptables, позволяющий анализировать произвольные байты в пакете. Используется для определения iOS по отпечатку.

**mangle** — таблица iptables для изменения свойств пакетов (например, маркировки). Используется в V3 для маркировки iOS-пакетов.

**Постквантовый алгоритм X25519 MLKEM768** — современный гибридный алгоритм шифрования, который должен поддерживаться доменом для корректной работы iOS-клиентов с Fake TLS.

**Маркер / SNI-валидность** — проверка, поддерживает ли домен постквантовый алгоритм. Если не поддерживает — iOS-клиенты не смогут подключиться без MSS.

**OpenSSL 3.5+** — версия библиотеки шифрования, необходимая для корректной работы SelfSteal с постквантовой криптографией.

**JA4 / JA4T** — отпечаток TLS-клиента, формируемый на основе его ClientHello. Позволяет идентифицировать тип устройства (iOS/Android/Desktop) и используемое ПО (браузер, Telegram и т.д.) без расшифровки трафика.

**JA3S** — отпечаток TLS-сервера, формируемый на основе его ServerHello. Показывает, какие алгоритмы шифрования и группы ключей поддерживает сервер.

**Сопоставление JA4 (клиент) и JA3S (сервер)** позволяет выявлять несоответствия между тем, что запрашивает клиент, и тем, что отвечает сервер.

**TLS-хендшейк (TLS handshake)** — процесс установления защищённого соединения между клиентом и сервером. Включает обмен ClientHello (клиент предлагает параметры шифрования) и ServerHello (сервер выбирает подходящие)

## Инструменты и термины проекта

**MEKO Launcher** — Единый лаунчер для управления всеми прокси (Telemt, MTG, MTProto.zig), панелями, установки фикса, настройки и обновления.

**Панель Telemt** — веб-интерфейс (от amirotin) для управления Telemt-сервером: просмотр статуса, пользователей, логов.

**SNI (Server Name Indication)** — расширение TLS, указывающее домен, к которому клиент пытается подключиться.

**Проверка SNI** — функция в проекте, проверяющая домен на поддержку постквантового алгоритма (через бота @Sni_checker_bot или встроенный чекер).

**Caddy** — веб-сервер с автоматическим SSL, альтернатива nginx для SelfSteal (не требует OpenSSL 3.5 на сервере).

**Комбайн** — неофициальный термин в сообществе для проекта, объединяющего несколько прокси и инструментов в одном меню.

## Процессы

**TCP-рукопожатие (TCP handshake)** — трёхэтапный процесс установления TCP-соединения (SYN -> SYN-ACK -> ACK).

**Мёртвое соединение** — Сокет, который сервер держит открытым, но клиент уже не активен (например, при сворачивании приложения). Фикс обрывает такие соединения за 2 минуты вместо нескольких часов простоя.

**Ретраи (Retries)** — повторные попытки подключения после неудачного соединения. REJECT ускоряет их, ускоряя подключение.

## Технические аспекты работы прокси с современными клиентами

### 🔬 Постквантовое шифрование и его роль

В основе современных TLS-соединений лежит алгоритм обмена ключами **X25519**. Долгое время он был стандартом, однако с развитием квантовых вычислений возникла необходимость в более устойчивых алгоритмах. Для этого был разработан постквантовый алгоритм **ML-KEM**.

Чтобы обеспечить совместимость между старыми и новыми системами, был создан **гибридный алгоритм X25519MLKEM768**, который сочетает в себе классический X25519 и постквантовый ML-KEM. Современные клиенты (включая iOS и браузеры) предлагают его по умолчанию.

Однако не все серверы способны обработать такой запрос. Это зависит от версии используемых библиотек:

- **OpenSSL ниже 3.5** и собранный на его основе **nginx** не поддерживают X25519MLKEM768.
- В результате сервер вынужден отвечать только через классический X25519.
- Современные клиенты (iOS, браузеры) ожидают от сервера ответ с гибридным алгоритмом X25519MLKEM768. Если ваш nginx собран на OpenSSL ниже 3.5, он физически не может ответить на такой запрос, так как не понимает новый формат. В результате сервер отвечает только через классический X25519, что создаёт несоответствие между ожиданием клиента и ответом сервера.

Для корректной работы с современными клиентами существует несколько решений:

- Использовать **Caddy** — он поддерживает гибридное шифрование из коробки.
- Установить **OpenSSL 3.5+** и пересобрать nginx под него.
- Использовать **заранее собранный бинарник nginx** с поддержкой OpenSSL 3.5.
- Использовать **публичный домен**, который уже поддерживает постквантовый алгоритм (в этом случае прокси будет проксировать его ответ).


### 📌 Практические рекомендации

1. **Если используете nginx** для SelfSteal — убедитесь, что на сервере стоит OpenSSL 3.5+ и/или nginx собран с его поддержкой. 

2. **Альтернатива nginx** — используйте Caddy, он работает с гибридным шифрованием из коробки.

3. **Если прокси не работает на iOS** — скорее всего, домен не поддерживает постквантовый алгоритм, и сервер отвечает через X25519. Проверьте домен через чекер.

4. **Если домен не поддерживает гибридное шифрование, но вам нужен именно он** — включите MSS (урезание размера пакетов), но учтите, что это сильно замедлит загрузку медиа.
