## Основные понятия для чайников

**MTProto** — протокол, используемый Telegram для шифрованного обмена данными между клиентом и сервером.

**MTProto-прокси** — сервер-посредник, который принимает подключения от пользователей и перенаправляет их к серверам Telegram.

**Telemt, MTG, MTProto.zig и тд.** — разные реализации MTProto-прокси на разных языках (Rust, Go, Zig). Все выполняют одну задачу — поднимают прокси для Telegram.

**SYN** — первый пакет в **TCP**-рукопожатии (трёхэтапное установление соединения).

**MSS (Maximum Segment Size)** — максимальный размер сегмента данных в TCP-пакете. Урезание MSS может быть использовано для починки прокси, но замедляет загрузку медиа.

**TLS** (**Transport Layer Security**) — протокол шифрования, который обеспечивает защищённую передачу данных между клиентом и сервером. Используется для **HTTPS**, защищает от прослушивания и подмены.

**Fake TLS** — маскировка прокси-трафика под обычный **HTTPS** (**TLS**).

**SelfSteal** — метод, при котором для Fake TLS используется SSL-сертификат реального сайта, подставленный на свой сервер.

**MiddleProxy** — режим работы прокси, при котором он не подключается напрямую к Telegram, а использует промежуточный прокси-сервер.

## Термины связанные с фиксом

**IPTables** — утилита, которая служит стандартным интерфейсом для управления работой межсетевого экрана (брандмауэра) Netfilter в ядре Linux. Она позволяет администраторам определять наборы правил для фильтрации, изменения и перенаправления сетевых пакетов. Правила организованы в цепочки, которые, в свою очередь, сгруппированы в таблицы по их назначению.

**NFTables** — современный фреймворк в составе подсистемы Netfilter ядра Linux, который призван заменить устаревшие инструменты iptables, ip6tables, arptables и ebtables. Он предоставляет более гибкий, эффективный и производительный способ фильтрации пакетов, трансляции адресов (NAT) и других манипуляций с трафиком. В отличие от iptables, nftables использует единый синтаксис для IPv4 и IPv6, не имеет предопределённых таблиц и цепочек, а также позволяет добиться более высокой производительности.
_Лаунчер в свою очередь позволяет использовать любой из подходящих вариантов для установки правил на сервере - как **iptables**, так и **nftables**, при установке правил лаунчер опишет кратко вам доступные варианты для применения на сервере._

**Фикс V1** — Разделение клиентов по портам: на один порт пускаются все устройства с SYN-лимитом 1 в сек. через DROP, на другой порт — iOS с урезанием MSS.

**Фикс V2(Старый MEKO ФИКС)** — один порт для всех устройств. iOS определяется по TTL+Length, применяется REJECT вместо DROP, SYN-лимит увеличен до 1 пакета в 1.1 сек, отключен MSS. _(**Telemt** вклеил себе наш фикс данной версии. 15.07 Этот же фикс у них был немного видоизменён, убрав отслеживание TTL и оставив только определение Length, выкатили ли они это в релиз - на момент написания не проверял)_

**Фикс V3** — как **V2**, но iOS определяется по полному отпечатку TCP-пакета (через u32/mangle) вместо TTL+Length. Более точное определение, сделали его, так как из-за балансировщиков на пути определитель на сервере по ттл+ленгтх в конечном итоге при некоторых факторах определит устройство неверно, отправит его не под тот набор правил и как следствие прилетит на сеть с которой подключалось устройство блокировка на 2 минуты. Проверено не одним десятком и не одной сотней тестов, _V3 справляется в 100% случаев, V2 даёт периодические сбои по операторам и регионам._
**Набор правил** версии **V3** проверяет через **u32** несколько фрагментов TCP (**по 4 байта каждый**) начиная со смещения в **32 байта** от начала **IP-заголовка**.

**Фикс V4 (Zapret2 MTProto fix by CHKRON)** — серверный обход через пакетный манипулятор **nfqws2** (zapret2). В отличие от V1–V3, которые ограничивают SYN-пакеты, V4 **активно вмешивается в TCP-рукопожатие**:  
- зажимает TCP window в SYN+ACK (`window=1400`) и в пустых ACK (`window=10`), вынуждая клиента дробить ClientHello;  
- режет первый data-пакет (ClientHello) на **3 части**, среднюю часть отправляет с **испорченной контрольной суммой (badsum)**
- клиент ретрансмитит битую часть → соединение устанавливается штатно.  
**iOS-клиенты** определяются по TCP fingerprint и пропускаются без вмешательства  (также, как это происходило ранее в **V3 версии**)
Требует установки **zapret2** (_скачивается автоматически с GitHub bol-van/zapret2_).  
_версия **V3** используется по умолчанию и рекомендуется к установке, так как **V4** является **не** универсальным методом, который бы работал у всех и находится на **этапе тестов** и **доработок**_

_Полные правила IPTABLES,NFTABLES, настройки zapret2 прописаны в [rules.sh](https://github.com/Mekotofeuka/MTPROTO_FIX_By_MEKO/blob/main/data/rules.sh)_

**SYN FIX / SYN Limit** — ограничение количества входящих SYN-пакетов с одного IP в секунду.

**REJECT vs DROP** — REJECT мгновенно сообщает клиенту об обрыве соединения (клиент сразу переподключается), DROP просто молча обрывает (клиент ждёт таймаут 3-5 секунд). REJECT быстрее.

**hashlimit** — модуль iptables для ограничения частоты пакетов

**TTL (Time To Live)** — поле в IP-пакете, указывающее, сколько узлов он может пройти. У iOS и Android/Desktop различается, используется для определения типа устройства.

**u32 (фильтр)** — модуль iptables, позволяющий анализировать произвольные байты в пакете. Используется для определения iOS по отпечатку.

**mangle** — таблица iptables для изменения свойств пакетов (например, маркировки). Используется в V3 для маркировки iOS-пакетов.

**Постквантовый алгоритм X25519 MLKEM768** — современный гибридный алгоритм шифрования, который должен поддерживаться доменом для корректной работы iOS-клиентов с Fake TLS.

**Маркер / SNI-валидность** — проверка, поддерживает ли домен постквантовый алгоритм. Если не поддерживает — iOS-клиенты не смогут подключиться без MSS.

**OpenSSL 3.5+** — версия библиотеки шифрования, необходимая для корректной работы SelfSteal с постквантовой криптографией.

**JA4 / JA4T** — отпечаток TLS-клиента, формируемый на основе его ClientHello. Позволяет идентифицировать тип устройства (iOS/Android/Desktop) и используемое ПО (браузер, Telegram и т.д.) без расшифровки трафика.

**JA3S** — отпечаток TLS-сервера, формируемый на основе его ServerHello. Показывает, какие алгоритмы шифрования и группы ключей поддерживает сервер.

**Сопоставление JA4 (клиент) и JA3S (сервер)** позволяет выявлять несоответствия между тем, что запрашивает клиент, и тем, что отвечает сервер.

**TLS-хендшейк (TLS handshake)** — процесс установления защищённого соединения между клиентом и сервером. Включает обмен ClientHello (клиент предлагает параметры шифрования) и ServerHello (сервер выбирает подходящие)

**Zapret2** — набор утилит для работы с сетевыми пакетами (**nfqws2**, **tpws**) с **Lua**-скриптами, позволяющий модифицировать **TCP**-потоки.

**nfqws2** — программа, работающая в фоне, которая перехватывает пакеты из NFQUEUE (netfilter), и применяет к ним **Lua**-скрипты (**disorder**, **badsum**, изменение размера **window**).

**NFQUEUE** — механизм в ядре **Linux**, позволяющий пользовательским программам обрабатывать пакеты, которые были направлены в очередь из правил **nftables**/**iptables**.

**out-range** — параметр zapret2, определяющий, какие исходящие пакеты сервера обрабатываются **Lua**-скриптом (по номеру пакета, по байтам, по последовательности и т.д.).

**split len** — размер каждой части, на которые разрезается первый **data**-пакет клиента при использовании **V4**.

**badsum** — отправка пакета с некорректной контрольной суммой **TCP**.

**disorder** — метод, при котором **пакеты** или их фрагменты отправляются в нарушенном порядке (перемешиваются).

**ClientHello** — первый пакет, который клиент отправляет серверу при установке **TLS**-соединения.

**Пакет** — блок данных, передаваемый по сети. В контексте TCP/IP содержит заголовки (IP, TCP) и полезную нагрузку (данные).

## Инструменты и термины проекта

**MEKO Launcher** — Единый лаунчер для управления всеми прокси (Telemt, MTG, MTProto.zig), панелями, установки фикса, настройки и обновления.

**Панель Telemt** — веб-интерфейс (от amirotin) для управления Telemt-сервером: просмотр статуса, пользователей, логов.

**SNI (Server Name Indication)** — расширение TLS, указывающее домен, к которому клиент пытается подключиться.

**Проверка SNI** — функция в проекте, проверяющая домен на поддержку постквантового алгоритма (через бота @Sni_checker_bot или встроенный чекер).

**Nginx** — высокопроизводительный веб-сервер, обратный прокси, балансировщик нагрузки и HTTP-кэш. В контексте MTProto-прокси используется в связке с **SelfSteal** для маскировки прокси под легитимный HTTPS-сайт. Для корректной работы с современными **iOS**-клиентами, которые требуют постквантового алгоритма **X25519MLKEM768**, **nginx** должен быть собран с **OpenSSL 3.5+**. В противном случае домен не пройдёт проверку **SNI**, и **iOS**-устройства **не** смогут подключиться к прокси.

**Caddy** — веб-сервер с автоматическим SSL, альтернатива nginx для SelfSteal (не требует OpenSSL 3.5 на сервере так как поддерживает гибридное шифрование из коробки).

**Комбайн** — неофициальный термин в сообществе для проекта, объединяющего несколько прокси и инструментов в одном меню.

## Процессы

**TCP-рукопожатие (TCP handshake)** — трёхэтапный процесс установления TCP-соединения (SYN -> SYN-ACK -> ACK).

**Мёртвое соединение** — Сокет, который сервер держит открытым, но клиент уже не активен (например, при сворачивании приложения). Фикс обрывает такие соединения за 2 минуты вместо нескольких часов простоя.

**Ретраи (Retries)** — повторные попытки подключения после неудачного соединения. REJECT ускоряет их, ускоряя подключение.

## Технические аспекты работы прокси с современными клиентами

### Постквантовое шифрование и его роль

В основе современных **TLS**-соединений лежит алгоритм обмена ключами **X25519**. Долгое время он был стандартом, однако с развитием квантовых вычислений возникла необходимость в более устойчивых алгоритмах. Для этого был разработан постквантовый алгоритм **ML-KEM**.

Чтобы обеспечить совместимость между старыми и новыми системами, был создан **гибридный алгоритм X25519MLKEM768**, который сочетает в себе классический **X25519** и постквантовый **ML-KEM**. Современные клиенты (включая **iOS** и браузеры) предлагают его по умолчанию.

Однако не все серверы способны обработать такой запрос. Это зависит от версии используемых библиотек:

- **OpenSSL ниже 3.5** и собранный на его основе **nginx** не поддерживают **X25519MLKEM768**.
- В результате сервер вынужден отвечать только через классический **X25519**.
- Современные клиенты (**iOS**, браузеры) ожидают от сервера ответ с гибридным алгоритмом **X25519MLKEM768**. Если ваш **nginx** собран на **OpenSSL** ниже **3.5**, он физически **не** может ответить на такой запрос, так как не понимает новый формат. В результате сервер отвечает только через классический **X25519**, что создаёт несоответствие между ожиданием клиента и ответом сервера.
- Проверка **SNI** выполняется через бота **@Sni_checker_bot** или встроенный чекер(для него необходим **OpenSSL 3.5** на сервере, где выполняется проверка)

Для корректной работы с современными клиентами существует несколько решений:

- Использовать **Caddy** — он поддерживает гибридное шифрование из коробки.
- Установить **OpenSSL 3.5+** и пересобрать nginx под него.
- Использовать **заранее собранный бинарник nginx** с поддержкой OpenSSL 3.5.
- Использовать **публичный домен**, который уже поддерживает постквантовый алгоритм (в этом случае прокси будет проксировать его ответ).


### Практические рекомендации

1. **Если используете nginx** для SelfSteal — убедитесь, что на сервере стоит OpenSSL 3.5+ и/или nginx собран с его поддержкой. 

2. **Альтернатива nginx** — используйте Caddy, он работает с гибридным шифрованием из коробки.

3. **Если прокси не работает на iOS** — Домен не поддерживает постквантовый алгоритм, и сервер отвечает через X25519. Проверьте домен через чекер. Если используете SelfSteal - убедитесь, что на сервере стоит OpenSSL 3.5+ и/или nginx собран с его поддержкой.

5. **Если домен не поддерживает гибридное шифрование, но вам нужен именно он** — включите MSS (урезание размера пакетов), но учтите, что это сильно замедлит загрузку медиа.

# Как сделать прокси из РФ напрямую, с работающим MiddleProxy(полезно для тех, кто использует "канал спонсор")

В данном мануале описан способ для запуска прокси напрямую на сервере, доступ с которого к ME/DC серверам телеграм ограничен. Работает с android/ios/desktop
1. Ставим скрипт MEKO
2. Ставим MTPROTO ZIG
3. Применяем фикс кнопочкой **1** 
4. Подключаемся к прокси и пользуемся
