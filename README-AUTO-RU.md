# Автоматическая установка Telegram MTProto-прокси

Неинтерактивный установщик отдельного экземпляра Telemt с SYN-фиксом MEKO V3
на nftables. Предназначен для Ubuntu 24.x–26.x на архитектурах x86_64 и arm64.

Это дополнение к оригинальному проекту
[Mekotofeuka/MTPROTO_FIX_By_MEKO](https://github.com/Mekotofeuka/MTPROTO_FIX_By_MEKO).
Ветка построена непосредственно поверх истории `upstream/main`; исходные
файлы, документация и лицензия MEKO сохранены. Автоматический установщик
добавлен отдельным файлом и не подменяет оригинальный `install.sh`.

## Что означает «не использовать порт 443»

Установщик никогда не выбирает локальный порт 443 для прокси. Он не закрывает
443, не останавливает работающий на нём сайт или панель, не освобождает порт и
не создаёт для него правил файрвола. Существующие сервисы на 443 остаются без
изменений.

Для MTProto выбирается случайный свободный порт из диапазона 10000–29999.
Перед установкой проверяется, что его не слушает ни TCP-, ни UDP-сервис. Эта же
проверка повторяется непосредственно перед запуском systemd, чтобы учесть
возможную гонку с другим процессом.

## Установка

```bash
curl -fsSL https://raw.githubusercontent.com/icelol/MTPROTO_FIX_By_MEKO/main/install-random-port.sh | sudo bash
```

При успешной установке stdout содержит ровно одну строку:

```text
tg://proxy?server=SERVER&port=RANDOM_PORT&secret=SECRET
```

Прогресс и ошибки выводятся в stderr, поэтому ссылку удобно получать в
автоматизации:

```bash
proxy_link=$(curl -fsSL https://raw.githubusercontent.com/icelol/MTPROTO_FIX_By_MEKO/main/install-random-port.sh | sudo bash)
printf '%s\n' "$proxy_link"
```

Повторный запуск идемпотентен: если установленный экземпляр исправен, скрипт
выводит прежнюю ссылку, не меняя порт и секрет.

## Дополнительные переменные окружения

Переменные необходимо явно передавать через `sudo`:

```bash
curl -fsSL URL/install-random-port.sh | sudo SNI_DOMAIN=rutube.ru PUBLIC_HOST=proxy.example.com bash
```

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `SNI_DOMAIN` | `rutube.ru` | Домен Fake TLS; перед установкой проверяется TLS 1.3. |
| `PUBLIC_HOST` | IPv4 определяется автоматически | Публичный IPv4 или DNS-имя для Telegram-ссылки. |
| `TELEMT_VERSION` | `3.5.5` | Версия Telemt; архив всегда сверяется с официальной SHA-256-суммой. |
| `PORT_MIN` | `10000` | Начало диапазона случайных портов. |
| `PORT_MAX` | `29999` | Конец диапазона случайных портов. |
| `PORT` | не задан | Необязательный фиксированный порт. 443 отклоняется, занятый порт прерывает установку. |
| `FORCE_REINSTALL` | `0` | Значение `1` меняет порт и секрет уже установленного экземпляра. |

## Какие проверки выполняются

- версия Ubuntu, архитектура процессора, права root и наличие systemd;
- свободный TCP- и UDP-порт с полным исключением локального 443;
- поддержка TLS 1.3 выбранным SNI-доменом;
- архив Telemt по официальной контрольной сумме SHA-256;
- правила nftables в отдельной таблице `tg_meko_proxy`;
- состояние systemd, локальный слушающий сокет и соединения Telemt с Telegram DC;
- активный UFW или firewalld: открывается только выбранный TCP-порт.

Прокси использует отдельные пути и службы, поэтому может работать рядом с
3x-ui, Hysteria, сайтом или другим экземпляром Telemt:

- `tg-meko-proxy.service`
- `tg-meko-proxy-synfix.service`
- `/opt/tg-meko-proxy`
- `/etc/tg-meko-proxy`
- `/var/lib/tg-meko-proxy`

Облачный файрвол или security group находится за пределами виртуальной машины.
Если он включён, выбранный TCP-порт необходимо разрешить у провайдера.
